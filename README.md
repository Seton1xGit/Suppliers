# Поставка

Сервис для первого выбора поставщиков food-бизнеса: поиск товаров и компаний, категории, подтвержденная доставка, сравнение 2-4 компаний, сохраненные и личные заметки.

Прототип: https://suppliers.178-236-242-240.sslip.io/

## Запуск

Нужен Node.js 22 или новее. Рабочий сайт не требует Node.js: папка `public` обслуживается любым статическим HTTP-сервером.

```sh
npm install
npm run dev
```

Адрес: http://127.0.0.1:4173

```sh
npm run validate
npm test
npx playwright install chromium
npm run test:browser
node tests/designs.mjs
```

Для проверки опубликованного сайта задай `TEST_URL` перед запуском браузерного теста. Тесты сравнивают реальные ID и порядок выдачи для Москвы, Петербурга, Новосибирска, Екатеринбурга, всей России и неизвестного региона. Проверяются направление наследования области и города, общероссийское покрытие, отсутствие подтверждения доставки, desktop и мобильная ширина, поиск и сочетание фильтров, пустой результат, сброс, лимит сравнения, удаление, заметки, перезагрузку, очистку, безопасный вывод текста и запрет localStorage. `tests/designs.mjs` дополнительно проверяет полный набор действий в каждом из 10 оформлений, все переходы с сохранением состояния, URL-приоритет, миграцию выбора и работу без storage. Снимки сохраняются в игнорируемую папку `test-results`, для оформлений в `test-results/app-designs`. Для обновления миниатюр галереи при локальной проверке задай `CAPTURE_GALLERY=1`.

## Данные и устройство

`public/data/catalog.json` содержит 45 разных компаний: 18 поставщиков ингредиентов, 15 готовой продукции и 12 упаковки. Поля `sources` и `verifiedAt` фиксируют официальные страницы и дату проверки. `delivery` содержит географию с отдельным источником и пояснением. Город компании не доказывает доставку. Значение `Россия` допускается при явном заявлении о доставке по стране; города не расширяются до областей. Подтвержденная доставка по области учитывается при выборе города внутри нее: соответствия явно перечислены в `cityRegions`. Москва и Московская область, Санкт-Петербург и Ленинградская область остаются разными территориями. Зональные ограничения сохранены в пояснении и источнике.

Для обновления записи проверь официальный сайт, контакты и условия, затем обнови дату. Для дополнительного условия нужны `value`, `sourceUrl`, `evidence`. Источник должен присутствовать в `sources`. Для цены также обязательны `product`, `unit`, `verifiedAt`, `conditions`. Неподтвержденные значения оставляй отсутствующими. После правки запускай валидацию и тесты. Постоянный `id` сохраняй при переименовании компании: по нему привязаны заметки.

`catalog-source.js` отделяет загрузку и поиск от интерфейса. `JsonCatalogSource` предоставляет `load()` и `search(items, filters)`. Будущий серверный адаптер может сохранить этот контракт. Ключи внешних API должны находиться только на сервере. Сейчас платных API и поисковых запросов при открытии сайта нет.

`deliveryMatch` различает региональное и общероссийское покрытие. Для выбранного региона сначала идет региональная группа, затем федеральная. Внутри группы точный товар выше частичного совпадения; при равенстве используется название. При неизвестном регионе показываются только поставщики с явной доставкой по России и пояснение об отсутствии региональных данных. Без выбранного региона виден весь каталог, включая записи с неизвестной доставкой. Фильтры хранятся в URL и сохраняются при обновлении страницы.

`storage.js` сохраняет IDs, сравнение и заметки в localStorage. При запрете записи сайт использует память и показывает предупреждение. Регистрации и синхронизации нет. Чужой текст выводится через `textContent` или `value`.

Каталог ограничен и обновляется вручную. Отсутствие данных означает, что они не найдены в проверенных источниках. Цены, наличие, сертификаты и окончательные условия необходимо запросить у поставщика. Рейтинга качества нет. Телефонная проверка поставщиков не проводилась.

## Размещение

На VPS файлы лежат в `/home/deploy/suppliers/releases/<release>`. Относительная ссылка `current` указывает на действующий релиз. Каталог `/home/deploy/suppliers` смонтирован в Caddy как `/srv/suppliers:ro`. Новый hostname обслуживает статические файлы. Существующий reverse proxy сохранен.

Загрузи содержимое `public` в новую папку релиза, затем выполни на VPS:

```sh
sh /home/deploy/suppliers/deploy-server.sh /home/deploy/suppliers/releases/<release>
```

Скрипт из `scripts/deploy-server.sh` нужно предварительно скопировать на сервер. Он сохраняет Caddyfile и compose в `backups`, валидирует конфигурацию до применения и после запуска, проверяет HTTPS и наличие минимум 45 записей. При ошибке возвращает конфигурацию и предыдущий релиз. Изменение mount требует пересоздания только Caddy, бот не пересоздается.

Для ручного возврата сайта переключи `current` на предыдущий относительный путь `releases/<release>`. Для возврата серверной конфигурации восстанови Caddyfile и docker-compose.yml из выбранной папки `backups`, затем выполни `docker compose --profile web up -d --no-deps caddy` в каталоге существующего compose. Перед применением проверь `caddy validate`. Секреты и SSH-ключи в репозитории отсутствуют.

## Интерфейс

Основное оформление нового посетителя - 03, "Таблица закупщика". Фильтры расположены над таблицей. На телефоне таблица прокручивается по горизонтали, действия закреплены справа. Переключатель в верхней панели открывает все 10 оформлений полноценного сервиса.

`app.js` управляет общим состоянием и действиями, `layouts.js` содержит адаптеры компоновки, `designs.js` задает список и правила выбора оформления. Поиск, сортировка, сравнение, сохраненные и заметки одинаковы во всех режимах. Дизайн хранится в том же ключе `suppliers:v1`, старые сохранения читаются без потери ID и заметок. При запрете или ошибке записи состояние остается в памяти.

Параметр `design=01` ... `design=10` в URL приоритетнее сохраненного выбора и совместим с `q`, `category`, `region`, `view`. Неизвестное значение дает 03. Смена оформления сохраняет текущие фильтры и выбор. Сброс фильтров и очистка сохраненного не сбрасывают оформление. В URL не передаются заметки или сохраненные ID.

Галерея `/previews/designs/` остается обзором. Старые адреса `01.html` ... `10.html` открывают нужное оформление главного сайта. Отдельных приложений для вариантов нет. Inter загружается с этого же сервера из `public/fonts`. Оригинальный файл шрифта и лицензия SIL OFL получены из официального [репозитория Inter](https://github.com/rsms/inter). Декоративных иллюстраций нет.

При выборе структуры изучены поиск поставщиков [Thomasnet](https://www.thomasnet.com/), регион и каталог [METRO](https://metro-cc.ru/), каталог компаний [Europages](https://www.europages.co.uk/). Размеры целей и сообщения об изменении выдачи сверены с пояснениями W3C к [2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) и [4.1.3](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html). Это ориентиры для проектирования, полная сертификация WCAG не проводилась.

## Демонстрация

Выбери Новосибирск, затем Екатеринбург: верхняя региональная группа изменится. Общероссийская группа останется после нее. Введи `стакан` и выбери упаковку. Открой источник доставки, добавь две компании к сравнению. Сохрани одну, напиши вопрос менеджеру в заметке и обнови страницу. Затем покажи поиск `7 ВЕРСТ` и сброс фильтров. Сохраненное остается в этом браузере.
