# Поставка

Сервис для первого выбора поставщиков food-бизнеса: поиск товаров и компаний, категории, подтвержденная доставка, сравнение 2-4 компаний, сохраненные и личные заметки.

Прототип: https://suppliers.178-236-242-240.sslip.io/

## Запуск

Нужен Node.js 22 или новее. Рабочий сайт не требует Node.js: папка `public` обслуживается любым статическим HTTP-сервером.

```sh
npm install
npm run dev
```

Адрес: http://127.0.0.1:4173

```sh
npm run validate
npm test
npx playwright install chromium
npm run test:browser
node tests/designs.mjs
node tests/tour.mjs
node tests/dialogs.mjs
node tests/terms-browser.mjs
node tests/mobile.mjs
node tests/comparison.mjs
```

Для проверки опубликованного сайта задай `TEST_URL` перед запуском браузерного теста. Тесты сравнивают реальные ID и порядок выдачи для Москвы, Петербурга, Новосибирска, Екатеринбурга, всей России и неизвестного региона. Проверяются направление наследования области и города, общероссийское покрытие, отсутствие подтверждения доставки, desktop и мобильная ширина, поиск и сочетание фильтров, пустой результат, сброс, лимит сравнения, удаление, заметки, перезагрузку, очистку, безопасный вывод текста и запрет localStorage. `tests/designs.mjs` дополнительно проверяет полный набор действий в каждом из 7 оформлений, все переходы с сохранением состояния, URL-приоритет, миграцию выбора и работу без storage. Снимки сохраняются в игнорируемую папку `test-results`, для оформлений в `test-results/app-designs`. Для обновления миниатюр галереи при локальной проверке задай `CAPTURE_GALLERY=1`.

## Данные и устройство

`public/data/catalog.json` содержит 105 разных компаний: 54 поставщиков ингредиентов, 32 готовой продукции и 19 упаковки. Поля `sources` и `verifiedAt` фиксируют официальные страницы и дату проверки. `delivery` содержит географию с отдельным источником и пояснением. Город компании не доказывает доставку. Значение `Россия` допускается при явном заявлении о доставке по стране; города не расширяются до областей. Подтвержденная доставка по области учитывается при выборе города внутри нее: соответствия явно перечислены в `cityRegions`. Москва и Московская область, Санкт-Петербург и Ленинградская область остаются разными территориями. Зональные ограничения сохранены в пояснении и источнике.

Для обновления записи проверь официальный сайт, контакты и условия, затем обнови дату. Для дополнительного условия нужны `value`, `sourceUrl`, `evidence`. Источник должен присутствовать в `sources`. Для цены также обязательны `product`, `unit`, `verifiedAt`, `conditions`. Неподтвержденные значения оставляй отсутствующими. После правки запускай валидацию и тесты. Постоянный `id` сохраняй при переименовании компании: по нему привязаны заметки.

`public/data/offers.json` содержит отдельные товарные предложения с постоянными ID, товаром, видом, фасовкой, единицей, типом цены, рынком B2B/розница, НДС, минимальной партией, регионом получения, источником и датой. Старые поля `supplier.price` оставлены для совместимости данных; интерфейс выбирает цену из предложений по текущему запросу.

`catalog-source.js` отделяет загрузку и поиск от интерфейса. `JsonCatalogSource` предоставляет `load()` и `search(items, filters)`. Будущий серверный адаптер может сохранить этот контракт. Ключи внешних API должны находиться только на сервере. Сейчас платных API и поисковых запросов при открытии сайта нет.

`deliveryMatch` различает региональное и общероссийское покрытие. Для выбранного региона сначала идет региональная группа, затем федеральная. Внутри группы точный товар выше частичного совпадения; при равенстве используется название. При неизвестном регионе показываются только поставщики с явной доставкой по России и пояснение об отсутствии региональных данных. Без выбранного региона виден весь каталог, включая записи с неизвестной доставкой. Фильтры хранятся в URL и сохраняются при обновлении страницы.

`storage.js` сохраняет IDs, сравнение и заметки в localStorage. При запрете записи сайт использует память и показывает предупреждение. Регистрации и синхронизации нет. Чужой текст выводится через `textContent` или `value`.

Каталог ограничен и обновляется вручную. Отсутствие данных означает, что они не найдены в проверенных источниках. Цены, наличие, сертификаты и окончательные условия необходимо запросить у поставщика. Рейтинга качества нет. Телефонная проверка поставщиков не проводилась.

## Размещение

На VPS файлы лежат в `/home/deploy/suppliers/releases/<release>`. Относительная ссылка `current` указывает на действующий релиз. Каталог `/home/deploy/suppliers` смонтирован в Caddy как `/srv/suppliers:ro`. Новый hostname обслуживает статические файлы. Существующий reverse proxy сохранен.

Загрузи содержимое `public` в новую папку релиза, затем выполни на VPS:

```sh
sh /home/deploy/suppliers/deploy-server.sh /home/deploy/suppliers/releases/<release>
```

Скрипт из `scripts/deploy-server.sh` нужно предварительно скопировать на сервер. Он сохраняет Caddyfile и compose в `backups`, валидирует конфигурацию до применения и после запуска, проверяет HTTPS и наличие минимум 100 записей. При ошибке возвращает конфигурацию и предыдущий релиз. Изменение mount требует пересоздания только Caddy, бот не пересоздается.

Для ручного возврата сайта переключи `current` на предыдущий относительный путь `releases/<release>`. Для возврата серверной конфигурации восстанови Caddyfile и docker-compose.yml из выбранной папки `backups`, затем выполни `docker compose --profile web up -d --no-deps caddy` в каталоге существующего compose. Перед применением проверь `caddy validate`. Секреты и SSH-ключи в репозитории отсутствуют.

## Интерфейс

Основное оформление нового посетителя - 01, "Таблица закупщика". Фильтры расположены над таблицей. На телефоне таблица прокручивается по горизонтали, действия закреплены справа. Переключатель в верхней панели открывает все 7 оформлений полноценного сервиса.

`app.js` управляет общим состоянием и действиями, `layouts.js` содержит адаптеры компоновки, `designs.js` задает список и правила выбора оформления. Поиск, сортировка, сравнение, сохраненные и заметки одинаковы во всех режимах. Дизайн хранится в том же ключе `suppliers:v1`, старые сохранения читаются без потери ID и заметок. При запрете или ошибке записи состояние остается в памяти.

Параметр `design` принимает `table`, `registry`, `workspace`, `dark`, `type`, `technical`, `search`. URL приоритетнее сохраненного выбора. Старые числовые ссылки сохраняют прежнее оформление; удаленные варианты 02, 04 и 07 открывают таблицу. Нумерация в интерфейсе идет от 01 до 07.

Галерея `/previews/designs/` остается обзором. Адреса `01.html` ... `07.html` открывают оформления в новой нумерации; адреса `08.html` ... `10.html` оставлены для совместимости. Отдельных приложений для вариантов нет. Inter загружается с этого же сервера из `public/fonts`. Оригинальный файл шрифта и лицензия SIL OFL получены из официального [репозитория Inter](https://github.com/rsms/inter). Декоративных иллюстраций нет.

При выборе структуры изучены поиск поставщиков [Thomasnet](https://www.thomasnet.com/), регион и каталог [METRO](https://metro-cc.ru/), каталог компаний [Europages](https://www.europages.co.uk/). Размеры целей и сообщения об изменении выдачи сверены с пояснениями W3C к [2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) и [4.1.3](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html). Это ориентиры для проектирования, полная сертификация WCAG не проводилась.

При первом посещении показывается тур из 4 шагов: поиск, доставка, сравнение, оформление. Его можно закрыть, пропустить, пройти назад или повторить кнопкой "Как пользоваться" в верхней панели. `tour.js` привязывает подсказки к текущим элементам во всех оформлениях. Флаг `tourSeen` хранится вместе с остальным состоянием и сохраняется при очистке компаний и заметок. При запрете storage флаг остается в памяти, поэтому после обновления страницы подсказки могут появиться снова. Название компании открывает ту же карточку, что и кнопка "Карточка и заметка".

## Демонстрация

Выбери Новосибирск, затем Екатеринбург: верхняя региональная группа изменится. Общероссийская группа останется после нее. Введи `стакан` и выбери упаковку. Открой источник доставки, добавь две компании к сравнению. Сохрани одну, напиши вопрос менеджеру в заметке и обнови страницу. Затем покажи поиск `7 ВЕРСТ` и сброс фильтров. Сохраненное остается в этом браузере.

Карточка компании и сравнение закрываются кликом по затемненному фону. Клик внутри окна и перетаскивание текста за его границы оставляют окно открытым. Проверка: `node tests/dialogs.mjs`.

Поиск учитывает связи конкретных товаров с общим ассортиментом в `product-search.js`: овощи, фрукты, рыба, молочная продукция, бакалея, специи, полуфабрикаты и упаковка. Связи сопоставляются с товарными позициями компании. Совпадения по группе помечены в выдаче, наличие конкретного товара нужно уточнять. Прямые совпадения имеют приоритет внутри группы доставки. Исходный ассортимент компаний не дополняется предположениями. Проверки: `node --test tests/product-search.test.mjs` и `node tests/search-browser.mjs`.

В карточке и сравнении стоимость доставки показана отдельно от цены товара и минимального заказа. Тарифы привязаны к региону, порогу заказа и способу получения; неизвестная верхняя граница остается пустой. Бесплатная доставка отображается как 0 рублей только с опубликованными условиями. Раздел особенностей показывает ограничения поставки и расхождения в источниках. Цена товара относится к конкретной позиции и единице, общий диапазон по несопоставимому ассортименту не рассчитывается.

На экранах до 900 px каталог превращается в вертикальные карточки. Поиск и город остаются сверху, направления прокручиваются в своей строке. Кнопки имеют высоту от 44 px, поля ввода используют текст от 16 px. Сравнение на телефоне и компьютере остается таблицей: слева закреплены параметры, сверху названия компаний. На узком экране рядом помещаются две компании, остальные доступны прокруткой и кнопками над таблицей. Длинные условия раскрываются в ячейке. Переключатель "Только отличия" скрывает одинаковые строки, включая одинаковые значения без данных; учитываются текст и ссылки на источники, поэтому одинаковая сумма с разными условиями не скрывается. Окна прокручиваются внутри, крестик остается сверху. Проверены ширины 320, 360, 390, 430, 700 и 844 px (последняя в альбомной ориентации) во всех семи оформлениях в Chromium с эмуляцией касаний. Нужна валидация на реальных iOS и Android устройствах.

Для мобильной компоновки использован подход каталога Shopify: поиск и фильтры перед списком, подробности отдельной позиции открываются по запросу. Проверена официальная [справка о поиске и фильтрации товаров](https://help.shopify.com/en/manual/products/searching-filtering). Чужие мобильные приложения на реальном телефоне не тестировались.

Для сравнения изучены официальные описания [закрепления столбцов в Airtable](https://support.airtable.com/articles/6540330000-Airtable-field-actions), [таблиц Notion](https://www.notion.com/help/tables) и [мобильных таблиц Coda](https://help.coda.io/hc/en-us/articles/39555863271053-Coda-mobile-app-basics). Airtable сохраняет контекст через закрепление полей. В Notion подробности записи доступны отдельно от общей таблицы. Coda позволяет вернуться от мобильных карточек к таблице и использует табличный вид для числовых данных. В нашем сравнении эти подходы применены к параметрам поставки, тарифам и раскрытию условий. Это сравнение способов работы с таблицами, рейтинг популярности приложений не составлялся.

До изменения сравнения сохранен релиз `20261102-12` и коммит `e2a812e`. При необходимости можно вернуть прежнюю версию через переключение серверного релиза. Данные каталога и сохраненные ID при этом совместимы.

## Сверка с заданием

- Поиск по категории реализован: ингредиенты, готовая продукция и упаковка. Товарный поиск учитывает конкретный ассортимент и общие группы с пояснением совпадения.
- Город и регион учитываются как место доставки. Город компании показан отдельно. Последние 20 компаний находятся в Екатеринбурге: 7 по ингредиентам, 6 по готовой продукции и 7 по упаковке.
- Основная информация собрана для 105 компаний: название, направление, товары, город, контакты, сайт, источники и дата проверки. Пять предыдущих новых компаний покрывают тесто, выпечку, десерты, дрожжи и закваски.
- Контакты и официальные источники есть у всех 105 компаний. Если телефон не опубликован, доступен сайт или форма связи.
- Для выбора поставщика есть сравнение 2-4 компаний, сохраненные и личные заметки. Контакты доступны из списка, карточки и сравнения.
- Минимальный заказ заполнен у 21 компании. При разных условиях по регионам или расхождении источников это указано в тексте. Для остальных нужен запрос поставщику.
- Товарные цены вынесены в отдельные предложения. Проверены 19 предложений свежих томатов от 6 компаний, включая 4 оптовые и 2 розничные. Дополнительно сохранены предложение слоеного теста и конфликтующая цена васаби. Цены этих товаров не подставляются друг другу. Полного прайса по всем товарам нет.
- Заявления о документах собраны у 2 компаний. Это сведения с сайта, действительность сертификатов и деклараций по конкретной партии требует проверки. Для остальных поле явно предлагает уточнение.
- География доставки подтверждена у 62 компаний. Числовые тарифы есть у 10; условия бесплатной доставки, платные варианты и неизвестный максимум разделены. У остальных цена запрашивается у менеджера.
- Регион работы отражен через город компании и подтвержденную доставку. Самовывоз и наличие регионального представителя не расширяют географию доставки.
- Заметки по поставщику сохраняются в браузере. Опубликованные ограничения, температурный режим, пороги заказа и противоречия источников вынесены в особенности. Синхронизации между устройствами нет.
- Прототип доступен по HTTPS, код находится в [репозитории](https://github.com/Seton1xGit/Suppliers). Репозиторий закрытый: перед отправкой HR нужно предоставить проверяющему доступ.
- Формат реализации: статическое приложение на JavaScript и JSON. Для ограниченного проверенного каталога этого достаточно, запуск не требует аккаунта и платных API. Автоматического сбора новых компаний и обновления цен нет; сведения обновляются вручную с повторной проверкой источников.

## Цены по товарам

Для проверки открой [помидоры с опубликованными ценами](https://suppliers.178-236-242-240.sslip.io/?q=помидоры&product=regular&priced=1). В таблице есть колонка "Цена товара", во всех остальных оформлениях отдельный блок. Можно выбрать вид, предложение компании, порядок цен и фильтр опубликованных цен. Выбор сохраняется в URL и браузере при смене оформления и обновлении страницы.

Сначала показываются предложения с ценой. Цены сортируются внутри одного вида, типа продажи, единицы, статуса НДС и ценовой ступени. Регион доставки остается обязательным фильтром. Розничные предложения отделены от опта; начальные цены отделены от фиксированных. Разные минимальные партии видны в условиях. Это сравнение опубликованных цен, наличие и окончательную стоимость подтверждает продавец.

За 1 кг цена пересчитывается только при подтвержденной массе оплачиваемой единицы. Например, в карточке Калининской базы отдельно указаны ящик 7 кг за 2093 руб. и цена 299 руб./кг. У Фуд Фреш для части позиций указаны число и короб, но единица цены не определена. Такие предложения не пересчитаны и не входят в общий ценовой порядок с руб./кг.

Покрытие зафиксировано в `public/data/price-coverage.json`: из 7 исходных компаний, попадавших в поиск томатов, у Фруктлайн найдены розничные цены; у Агропарк СПБ, 4 Овощебазы, Экватора и ИННДА цена запрашивается у менеджера; у ЛигаЛес и Дары Сибири свежие томаты не подтверждены. Добавлены Фуд Стар, Фуд Фреш, Софийская база, Калининская база и Фермерский Дворик Екатеринбурга. Доступны предложения Москвы, Петербурга и Екатеринбурга с ограничениями получения. Это не покрытие всех товаров и всех поставщиков ценами.

Проверки: `node --test tests/offers.test.mjs`, `node tests/prices-browser.mjs`, `node scripts/validate.mjs`. Перед обновлением товарных цен сохраняется предыдущий серверный релиз. Источники не запрашиваются от имени пользователя, закрытые прайсы не подменяются розничными.

Массовые партии хранятся отдельно в `public/data/imported-offers.json`, ручные проверенные предложения остаются в `manual-offers.json`. Первая партия: 462 строки публичного HTML-прайса Фуд Стар, из них 459 новых предложений и 3 сохраненных ручных записи. Всего после объединения 480 предложений. В прайсе есть овощи, фрукты, ягоды, зелень, орехи и сухофрукты. Это ассортимент одного поставщика, не 462 поставщика.

Повторяемая загрузка: `python scripts/import_prices.py --source food-star`. Для проверки на сохраненном HTML без обращения к сайту используется `--input путь.html`. Адаптер выполняет fetch/parse и возвращает нормализованные предложения; записывает постоянные ID, метаданные источника и отчет в `price-sources.json`. Повторная загрузка заменяет только свою партию, ручные предложения сохраняются. Будущий API подключается отдельным адаптером с тем же выходным форматом. Ключи API должны находиться в серверном окружении импортера, в браузер они не передаются. Внешний API сейчас не подключен.

Вторая партия добавила 171 активную розничную позицию из открытой витрины Сибирского продукта, 25 десертов Cake Me из публичного JSON витрины с пагинацией и 16 позиций упаковки ПакТочка. Всего импортировано 671 предложение: 459 по ингредиентам, 196 по направлению готовой продукции, 16 по упаковке. Вместе с ручными записями 692 предложения, из них 691 с опубликованной числовой ценой и одно с противоречием источников. Это не полный ассортимент 105 компаний.

Команды: `python scripts/import_prices.py --source sibprod`, `--source cake-me`, `--source packtochka`. Эти адаптеры загружают открытые витрины; Cake Me обходит страницы публичного JSON, тот же запрос выполняется сайтом магазина. Закрытые личные кабинеты не используются. Сибирский продукт помечен как розница, у ПакТочки и Cake Me тип опубликованного тарифа не указан. Для упаковки без подтвержденной единицы цена сохранена без пересчета. Для десертов подтверждена масса порции: на первом месте исходная цена порции, рядом пересчет для сравнения.

`public/data/offers.json` является общей опубликованной витриной: в нем объединены ручные и импортированные предложения. Интерфейс читает этот файл один раз. `manual-offers.json` и `imported-offers.json` нужны для раздельного обновления источников без потери ручной проверки.
